# 设计取舍

最后更新：2026-10-09（北京时间）；Codex。当前源码版本由测量目录的 HEAD + SHA256 标识。

## 分工与算法选择

用户改为助手完成所有核心。steal 使用互斥 deque；Arena 用对齐 bump + 批量 reset，Pool 使用空闲块内部链表。不存在脱离负载的“最佳算法”：mutex deque 容易证明 exactly-once，Arena 适合整体释放，Pool 适合有上限的同尺寸对象；不同生命周期不可只按吞吐排总榜。

## L1：减少对照混杂

旧池每任务完成都广播、全局状态锁与轮询会带来开销。perf 的旧版 787 样本中，52.10% 落在负载调用，7.37% 在 kernel spin unlock，后者多经 futex wake / try_to_wake_up；stat 有 66765 次上下文切换。它确认唤醒开销存在，不能单独证明历史 4-worker 异常因果。

新池按 worker 通知、pending 归零才通知 drain，采用同一个执行器开关 cross-queue stealing。保留必要的队列锁 / 生命周期锁，不在无证据下改为 lock-free。预入队与端到端分开，粗负载与微任务分开，完整预热、10 轮、后台负载、逐 ID 校验与串行参考均入证据。增加 8 workers 是四核主机上的过量订阅实验，不承诺线性扩展。

## L2：替换无法区分实现的指标

用整批计时摊薄时钟成本；分位数命名为 batch ns/op。加入 malloc 通用基线和非整齐大小，明确写入成本、校验记录表和回收语义。固定 pool 不需要连续空闲，删除外部碎片结论；另建全空间填满后隔块释放的 first-fit 示例，验证大请求失败及合并恢复。

保留 pool live bitmap / stack 记录表，用于可复现的非法释放检查，并输出元数据成本；删除检查会改变被测实现，不把当前数字冒充无检查分配器。Arena 不逐对象析构，通用对象仍需调用方处理析构。

## 验证边界

Release、TSan、ASan/UBSan 分开构建。TX 的 TSan 映射问题用进程级 setarch -R 处理；LeakSanitizer 最初因权限 / ptrace 限制全部失败；使用 sudo 测试进程且 detect_leaks=1 后 8/8 通过。普通用户关闭泄漏检测的 ASan/UBSan 也为 8/8，两个口径单独保留日志；不是将关闭泄漏检测称作无泄漏。旧测量与旧分工只作为历史保留。

## 本轮评审：成本不均与尾部观测

为区分任务数量与任务成本，添加任务数均分、稀疏100倍迭代的计算量偏斜；不将它写成随机生产负载。批量计时用于均摊成本，单次instrumented通道用于观测孤立停顿，保留clock+write控制与逐窗口最大值，不对分位数做减法。计时插桩会扰动系统；两种方法不能混为相同吞吐或固有尾延迟。

Arena每批一次reset，旧结果除以256没有单次操作含义；以空字段和unresolved_single_reset明确表达测量未解析出成本。Pool/Stack/Arena不作跨机排序，malloc收益也限定到本机热小对象场景。

loadavg不是背景活动计数。旧微负载耗时8.54秒、紧随粗负载，在一分钟平均中会保留历史影响。端到端提交耗时增长支持“微任务下执行器开销主导”的观察，不单独证明全部来自唤醒；若需因果归因，应匹配输入并控制通知/锁变量，另行profile。

## 随机成本布局

保留周期性重任务作为成本偏斜上界案例，同时新增固定重任务总数、位置随机无放回的对照。总迭代量匹配，轮转放置任务数均分；同种子配对不同策略，种子每轮变更且记录布局hash、每队列重任务数。成本向量提前构建，只读共享，避免在计时中生成随机数；参考求和应用同一布局。十个种子的波动混有布局和运行噪声，不能按同输入重跑误差解释，也不预设收益方向。

## 2026-10-09 负载维度与冷路径分离

随机位置不等于成本分布覆盖。保留旧固定重量证据，新加占比 / 倍数参数及整数区间均匀成本；配对只共享同轮形状，不强行使跨配置总工作相同。默认常规矩阵加入随机版，昂贵参数扫描另有入口。来源 bc9c6db + 本轮修改，精确哈希见新测量目录。

冷路径单列首次触页与存活集增长，匿名映射 / 预触页为控制，malloc 内部扩容不可由调用次数推定。当前自定义分配器构造时初始化固定缓冲区，强行标为“首次触页分配”会混淆构造与分配；因此不伪造四分配器冷路径排名。废弃参考别名无调用方，删除；历史报告保留原哈希。status 只保留一份当前摘要，progress 说明恢复到条目前。

## 2026-10-13 L3 资源加载（Codex）

来源 bee55fd + 本轮修改。真实热文件+合成CPU解码，复用L1工作线程；主线程有限提交、在途8上限、重复去重和失败传播。三模式十轮、2880帧，checksum全部一致。p99跨轮中位数sync6.498ms/async1.739ms/preload0.297ms；预加载startup17.679ms，异步缺失资源×帧数48；分别报告代价，不称真实渲染收益。Release/TSan/ASan/UBSan/启用泄漏检测11/11；初次编译发现JobSystem仅future<void>，采用Asset packaged_task封装，未改其已有接口。源码SHA256核对通过，数据见measurements/2026-10-13-l3/，不含GPU上传/冷磁盘。


## 2026-10-15：把调度、内存与资源安装串联（Codex）

- 复用 L2 Arena，但不改变 128 字节 Pool 的块契约。建立 8 个64KiB槽，worker独占lease；只在领取/归还持锁，RAII覆盖异常，scratch shared_ptr随任务保活；安装资产不持scratch指针。启动清零/触页与512KiB容量都公开计入代价。不是泛化通用线程安全分配器，也不能宣称整个流水线零分配。
- 普通 vector 保留为默认。单轮近尾数据的差异与异步 A/A 的波动重叠；“接入场景”不意味着应无证据地换默认。提供运行时切换才方便同版本验证。
- request延迟从首次受理起，demand延迟从首次需求起，两者区别为入队背压等待。安装时刻由owner commit记录，包含每帧2次提交预算；保留缺失累计而不是用一个p99替代所有体验指标。
- 3 workers对照用于过量订阅敏感性，不当抢占因果证明。记录Linux所有vCPU的guest steal，并明示无法归因到单线程、0不排除guest内部竞争。A/A控制固定输入同实现，轮换和逆序降低顺序偏差，但十轮不是统计保证。
- L2已有预触页控制，补setup耗时和缺页，避免把初始化移出表格后宣称使用阶段“免费”。mmap只映射，不用mlock承诺驻留，不把Linux写触页称作跨平台commit。

## 2026-10-23 第 1 阶段：工具与数据的取舍（Claude Code）

- **FBX 解析选 ufbx 而不是 Assimp**：在 Bistro 三个文件上两者三角形数一致，所以选择不影响负载本身；ufbx 只有一个 C 文件，许可为 MIT 或公有领域，加载快约一倍，峰值内存约一半，网格与 FBX 对象一一对应，便于把包围盒对应回原场景。代价是只支持 FBX 和 OBJ，以后要读别的格式得另换库。它只出现在 `tools/` 的预处理程序里，核心库不依赖它。
- **外部库从源码按同一标签构建，不用 apt 包**：apt 版本（oneTBB 2021.11、jemalloc 5.3、gperftools 2.15）比最新标签旧，Windows 上又拿不到 apt 包；用同一标签，“与外部库对比”在两台机器上才是同一个对手。代价是构建时间，以及要自己维护编译选项（写进 device.json）。
- **Windows 用 VS2022 自带的 CMake**：和 MSVC 工具链同源，不在用户机器上多装一套软件。
- **luowindows 的线程编号规则**：逻辑线程 0–15 是 8 个性能核（每核两线程），16–31 是 16 个能效核。只在性能核上做的“平滑扩展”实验，最多 8 线程且每核只用一个逻辑线程；超过就标“超线程”或“混合核”，不作平滑扩展的结论。


## 2026-10-24 第 2 阶段外部基线适配（Codex）

- 外部库固定标签与提交，只消费具有匹配成功构建回执的用户目录安装，不回退到系统版本；缺失时 CTest 明确 Skipped。避免不同库版本混入一致性或后续性能比较。
- oneTBB 用 task_arena/task_group，Taskflow 逐任务 emplace，以保持逐 ID 调度校验。std::async 采用 T 个分片，区别于每项创建一个线程；后续比较必须保留这个执行模型说明。
- 分配器分别链接同源码回放程序；通过版本、归属接口与 Linux malloc 提供方确认真实分配器。当前串行 trace 回放只证明正确性，多线程性能留给 S4。
- 缺失 autotools 仅在用户数据目录解包固定版本工具；jemalloc 显式设置已核实版本；Google 复用已有缓存并导出完整静态依赖闭包。这保持本轮构建可用，但 Google 空机器重建仍需补齐缓存准备，未声称已解决。

构建、链接与复现细节见 [baselines.md](baselines.md)。本阶段没有新的性能结论。

## 2026-10-25 阶段3：队列、通知与分块（Codex）

- Chase-Lev使用固定容量+SC索引/原子槽，任务存储保留到join，先减少弱内存序与回收证明负担；不宣称全执行器无锁。外部生产者经inbox由owner转移，四个自研策略共用实验池；保留原JobSystem用于S2与L3，不把两个执行器吞吐直接拼表。
- Bistro真实操作成本冻结后16倍时间压缩并换算为工作单位，用确定性重采样保留近似成本形状。主动区分成本代理与真实引擎任务，采集表/校准/压缩都在数据指纹材料中。
- 条件通知仅改变sleeping时notify，仍保留generation发布；先做profiling再选择，不同时叠批提交。吞吐和p99六组均无显著收益，默认仍旧策略。单次futex10266→10248不当作降调用证明。
- 细任务分块后可相对串行显著改善，但大块降低可并行任务数量；接口放在核心之上，保留block1回退。临界粒度只报告离散采样点，理想并行偏差不等同纯调度耗时。
- A/A范围重叠时即便中位数较高也判无显著提升。完整论据、代价和反证见stories/S1–S3.md，原始数据见measurements/2026-10-25-phase3-tx/。
