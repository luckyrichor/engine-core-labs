# 现状与边界（一页）

最后更新：2026-10-09（北京时间），Codex；精确代码版本见本轮测量元数据。

## 已实现

L1：owner LIFO / thief FIFO 的 mutex deque；future 异常传播、拒绝关闭后提交、drain、worker 通知代数、外部暂停 / 恢复；多生产者和逐 ID exactly-once 验证。所有算法由 Codex 完成。

L2：固定块内部空闲链表 Pool、带合法性记录的 LIFO Stack、对齐 bump Arena、字节粒度 first-fit / 合并示例。无用户手写 TODO；新测量包含 malloc。

## 数据怎么读

旧轮目录为 `docs/measurements/2026-10-09/`，对应 2ea3b9a 的测量；新评审测量见 `docs/measurements/2026-10-09-review/`。L1 coarse 与 overhead 各 320 次、每配置 10 轮；含提交与预入队分开。实际任务 / 迭代数、逐次主机负载和 SHA256 在 device.json。粗负载实际每次 0.241–1.031 秒，微负载刻意观察同步开销。曲线是本机四核虚拟机的数据，八线程是过量订阅。

旧版 perf 的 787 个 CPU 样本和 stat 确认唤醒开销存在，无法单独证明旧异常曲线的全部因果。新版基线与 stealing 共用 executor，减少脚手架混杂；不按不同负载的旧新数字计算加速比。

L2 共 80 行批量测量，每批 256 次；报告批均摊分位数，包含每块 1 字节写入。malloc 是通用基线，Arena 回收是一次 reset，生命周期不同。odd 尺寸暴露对齐浪费；bookkeeping 明示 bitmap / Stack 记录成本，malloc 内部开销未知。

## 边界

- 当前实现用互斥队列，仍有锁、原子和 future 开销；未实现 Chase-Lev，也未证明无锁方案必要。不能在池内等待 / 关闭自己所属的池，pause / shutdown 由外部串行控制。
- 单次性能不能证明“4 线程优于 8 线程”；看完整 10 轮、标准差和不同负载。主机负载被记录；loadavg 含历史活动，不能当作后台争用证据。
- 固定 Pool 没有连续空闲要求；碎片示例必须用变长连续请求。Arena reset 不负责调用析构，分配器非线程安全。
- TSan / ASan/UBSan 是所测路径的动态检查，不证明所有并发时序正确。本轮 Release、TSan、ASan/UBSan、启用泄漏检测均 8/8 通过；TSan 使用进程级 setarch -R，泄漏检测需 sudo 的测试进程。
- L3 资源加载实验未实现；当前不是生产引擎或完整岗位能力证明。

## 2ea3b9a 版本数值摘要（历史证据）

粗负载实际 10000 × 50000。均衡基线预入队中位数（1/2/4/8 workers）：10590 / 20935 / 37161 / 36958 任务/秒；四、八线程 CV 分别 15.8% / 9.6%，不以中位数微小差距判定优劣。集中队列四线程窃取 38037，对照 10572 任务/秒，约 3.6 倍，限定于此负载。运行时一分钟 loadavg 范围 0.60–4.10，该数值不能单独判断后台活动。

L2 aligned 的跨轮 batch-p50 中位数：Pool 4.70、Stack 4.27、Arena 2.15、malloc 6.62 ns/op；相邻两次读时钟的中位数 30ns，摊到 256 次约 0.117ns。odd 模式 Stack / Arena 补白 3009 字节；Pool bookkeeping 576、Stack 65600、Arena 64 字节（包含对象对齐补白和预留记录）。这些是本机观测，不建立跨机器分配器排名。新方法将 Arena 单次 reset 标为未解析成本。

## 新评审补充

任务数均分、0.79%任务做100倍计算的heterogeneous负载已加入；不是随机生产分布。L2新增102400次逐次计时 / 行、clock+write控制和400个窗口最大值，批均摊p99与单次观测分开。逐次观测含计时和系统噪声，不能当作分配器固有尾延迟。Arena reset实际一次，删除除以256的单次成本解释。六项审查与微任务解读见 [评审记录](review-2026-10-09.md)。
